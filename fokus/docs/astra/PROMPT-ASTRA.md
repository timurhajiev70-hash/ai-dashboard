## Что проверяешь
**Fokus** — личный дневник задач с приоритетами для врача с собственной практикой (Германия, ПО tomedo).
Не список дел, а инструмент выбора «что делать первым»: каждая задача проходит мастер из 6 вопросов
(важность, срок, последствия, кто делает, длительность, зависимость), получает балл 0..100 и группу
(🔴 очень важно / 🟠 приоритет / 🔵 очередь / ⚪ поручить / ⚫ отложено / ⏸ ждёт).
В день — не больше 3 главных задач; 4-ю добавить нельзя, только заменить. Невыполненные переносятся
на завтра со счётчиком; после 3 переносов или 7 дней без пересмотра система просит пройти вопросы заново.

Версия 2: интерфейс в стиле Todoist (боковая панель, список с круглыми чекбоксами, быстрый ввод по клавише `q`,
панель задачи), проекты Praxis / Privat / Projekt (+ свои), «Входящие» (задачи без оценки), Google Календарь
только для чтения по секретному iCal-адресу, запуск как приложение `Fokus.app` из Dock, MCP-сервер для Claude.
Стек: Python 3.9+ **только стандартная библиотека**, SQLite, одна HTML-страница без зависимостей,
локально на Mac (`http://127.0.0.1:4321`). Запись в Google Календарь, телефон, Todoist — не в этой версии, не предлагай.

## Что уже найдено и исправлено предыдущим аудитом (не повторяй, ищи глубже)
Сделанная вчера задача дня «зависала» после смены дня; удалённые задачи можно было менять через API;
сбой бэкапа валил сервер трейсбеком; двойной клик создавал дубли; вкладка не замечала смену дня;
rollover можно было крутить назад/в будущее; `Infinity`/огромные id давали 500; названия из невидимых
символов проходили; не-строки в `depends_on` уводили задачу в «ждёт»; тексты про лимит были зашиты под 3;
в MCP — падения на суррогатах и глубоко вложенном JSON, отсутствие валидации enum, тест гасил рабочий сервер;
в v2 (до тебя) — раскладка сетки, фокус модалок, потеря текста композера при перерисовке.

## Где копать (гипотезы автора — подтверди или опровергни)
1. **Формула приоритета** (`AGENTS.md` §5, `engine.py`): составь свою таблицу 15–20 реалистичных задач
   врача (обезличенных) и покажи, где балл/группа противоречат здравому смыслу или матрице Эйзенхауэра.
   Особенно: задача со сроком «сегодня» средней важности попадает в 🟠 и не может быть выбрана в день;
   вес длительности переключает группу; просроченная задача держит максимальную срочность вечно;
   пороги вплотную; веса из настроек с крайними значениями.
2. **Перенос дня и переоценка** (`engine.plan_rollover`, `db.apply_rollover`, `server.auto_rollover`):
   сценарии на 2–4 недели вперёд — задача manual в ⚫, задача ⏸ с устаревшей зависимостью, поручённая задача,
   выполненная и возвращённая, день с лимитом 1 и 10, смена `day_limit` при выбранных задачах, часовой пояс
   и сервер, работающий через полночь, перевод часов (DST в Германии).
3. **Данные**: транзакции и один `Lock` в `server.py`; что будет при повреждённом `fokus.db`, при `-wal`-файле
   без прав, при 10 000 задач и 100 000 записей журнала; бэкап при каждом запуске — где это ломается;
   мягкое удаление и журнал — можно ли восстановить задачу; миграции схемы при будущих версиях (их нет —
   это проблема?).
4. **Безопасность локального приложения**: `http.server` на 127.0.0.1 без аутентификации — что может сделать
   вредоносная страница в браузере пользователя (CSRF через форму без `Origin`? DNS rebinding? `localhost`
   с другим портом?); XSS в `index.html` (ищи `innerHTML`, `insertAdjacentHTML`, атрибуты `on*`, `href`);
   инъекции в SQL (`db.py` — все ли запросы параметризованы, в т.ч. `ORDER BY` и `UPDATE` по словарю полей);
   path traversal; JSON-бомбы; MCP — что сможет сделать вредоносный MCP-клиент или подменённый `server.py`.
5. **macOS-специфика** (`Fokus.command`): bash 3.2, Gatekeeper/карантин для `.command`, `python3`
   без Command Line Tools, симлинк на рабочем столе, пробелы и кириллица в пути к папке, iCloud Drive,
   повторный запуск, закрытие окна Терминала (SIGHUP) — остаётся ли сервер.
6. **Интерфейс** (`index.html`): состояние мастера при переключении вкладок, повторная оценка,
   клавиатура, ошибки сети посреди действия, 200 задач на доске, длинные названия, DE-перевод (смысл, не только
   полнота), крупность текста для 60+.
7. **Качество кода и сопровождаемость**: дублирование констант между `engine.py`/`db.py`/`mcp_server.py`;
   рассинхрон спецификации и кода (найди места, где `AGENTS.md` говорит одно, код делает другое);
   совместимость с Python 3.9 (синтаксис, `typing`, `datetime.fromisoformat`); тесты — что они НЕ покрывают.
8. **Приватность**: правило «никаких имён пациентов — только номера tomedo» держится только на подсказке
   в поле ввода. Предложи, как это проверять, не мешая работе.
9. **Проекты и Входящие** (`db.py`, `server.py`, `engine.parse_quick_add`): `#Тег` в названии, коллизии slug,
   архив проекта по умолчанию, удаление проекта с задачами, задача из Входящих в «Сегодня», перенос дня для inbox.
10. **Google Календарь** (`calendar_ics.py`, `/api/calendar*`): RRULE-краевые случаи (UNTIL с Z и без, BYDAY с
    номерами, EXDATE с TZID, RECURRENCE-ID), переход на зимнее/летнее время, многодневные события, 5 МБ ICS,
    бесконечные повторы, недоступный хост, утечка секретного адреса в логи/ответы/ошибки, SSRF через адрес.
11. **Fokus.app** (`Fokus.app/Contents/MacOS/Fokus`): bash 3.2, симлинк на рабочем столе, пробелы и кириллица
    в пути, PATH из Finder, карантин Gatekeeper, браузер в режиме `--app=`, остановка сервера.
12. **Интерфейс как продукт**: что бы Todoist сделал иначе — 10–15 конкретных пунктов с приоритетом.

## Правила
- Каждое замечание — с местом (`файл:строка` или функция) и способом воспроизведения (команда, запрос,
  python-фрагмент или последовательность действий в UI). Если не можешь воспроизвести, а только подозреваешь —
  пометь «гипотеза» и объясни, как проверить.
- Ложное срабатывание хуже пропуска: перед включением в таблицу перепроверь по коду.
- Не предлагай сторонние библиотеки, фреймворки, облако, переписывание на другой язык.
- В примерах только обезличенные данные: пациент — «tomedo #48213», без имён.
- Если можешь выполнять код — распакуй файлы, запусти `python3 -m unittest discover -s tests`
  и сервер (`FOKUS_PORT=4399 FOKUS_DB=/tmp/f.db FOKUS_TODAY=2026-10-26 python3 server.py`), проверяй живьём.

## Формат ответа
Сначала таблица (сортировка по серьёзности):

| № | Серьёзность | Где (файл:строка) | Что не так | Как воспроизвести | Как исправить (конкретно) |
|---|---|---|---|---|---|

Серьёзность: **критично** — теряются данные, падает сервер, задача попадает не в ту группу, можно добавить
4-ю задачу дня, не работает перенос/переоценка; **важно** — неверное поведение в реальном сценарии
или уязвимость; **мелочь** — неудобство, неточный текст, косметика; **предложение** — спорное улучшение.

Затем: «Что хорошо» (3–5 строк), «Чего не хватает в тестах» (список), «Вопросы владельцу» (решения,
которые должен принять пользователь, а не программист), «Вердикт»: можно ли пользоваться ежедневно и что
обязательно исправить до этого.
