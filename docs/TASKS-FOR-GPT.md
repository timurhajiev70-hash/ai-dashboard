# Задачи для более дешёвых моделей (GPT Sol / Terra / Luna и т.п.)

Каждый промпт самодостаточен: копируете блок целиком в чат модели, результат присылаете мне (Claude) на проверку.
Общее правило для всех задач: модель не придумывает факты; если не уверена, пишет `null` или `unknown`.

## Обзор

| № | Задача | Вход | Выход | Моя проверка |
|---|---|---|---|---|
| 1 | Модели, лимиты, цены систем | список систем | JSON `System[]` | выборочно по источникам |
| 2 | 15 правил подбора | схема Rule | JSON `Rule[]` | валидация + прогон через `/api/recommend` |
| 3 | URL-передача промпта | список систем | таблица с доказательствами | ручная проверка ссылок |
| 4 | Smoke-тест UI | схема и экраны | один скрипт | запуск на моём сервере |
| 5 | Немецкий перевод UI | список строк | `locale-de.json` | сверка ключей |
| 6 | SVG-иконки систем | список систем | SVG-файлы | валидация + визуально |
| 7 | Ревью `server.js` на безопасность | код + чек-лист | отчёт по пунктам | перепроверяю найденное в коде |

````text
Ты помощник по сбору фактов. Сегодня дата: <ПОДСТАВЬ СЕГОДНЯШНЮЮ ДАТУ, ГГГГ-ММ-ДД>.
Для каждой системы из списка найди АКТУАЛЬНЫЕ на сегодня данные на официальных страницах (сайт вендора, страница цен, документация): какие модели доступны, какие тарифы подписки, лимиты и стоимость, есть ли отдельный доступ по API.
Системы: ChatGPT (chatgpt.com), Claude (claude.ai), Gemini (gemini.google.com).

Верни ТОЛЬКО JSON-массив объектов такого вида (все поля обязательны):
{

Правила:
- Цифры только из найденных источников. Если данных нет, пиши "unknown" (для apiAccess) или "не найдено" (для текста).
````

## 2. 15 дополнительных правил подбора (Rule)

**Что вставить:** промпт ниже.

**Формат ответа:** JSON-массив из 15 объектов `Rule`.

**Как проверю:** валидирую поля и уникальность `id`; проверяю, что `requiredTools` ссылаются на существующие инструменты; прогоняю по 2 тестовые фразы на правило через `/api/recommend`; смотрю пересечения ключевых слов.

````text
Ты помогаешь написать правила подбора ИИ-системы под задачу. Правило описывает тип задачи и какие инструменты для неё нужны.

Формат одного правила (JSON):
{
  "id": "find-email",                    // slug латиницей, уникальный
  "name": "Найти письмо",                // по-русски
  "keywords": ["письм", "почт", "mail", "gmail", "email"],
                                         // подстроки, регистронезависимо; русские в виде основы (без окончаний), плюс английские варианты
  "requiredTools": ["gmail"],            // ТОЛЬКО из списка: gmail, calendar, drive, github, browser, files, terminal, figma, todoist, obsidian, skills
  "capabilities": ["поиск по почте"],    // что нужно уметь, по-русски
  "preferredSystems": ["claude", "chatgpt"], // из: chatgpt, claude, gemini; может быть []
  "promptTemplate": "Найди в моей почте: {task}. Покажи отправителя, дату и краткое содержание.",
                                         // обязательно содержит {task}
  "priority": 10,                        // целое 1-20; выше = важнее
  "demo": false
}

Задание: придумай 15 НОВЫХ правил для личной панели врача-терапевта, открывающего практику, который также пишет код. Не повторяй уже существующие: найти письмо, исправить сайт, изучить исследования, написать Android-приложение, подготовить документ, обработать локальные файлы, календарь, задачи.
Примеры тем: заметки в Obsidian, дизайн в Figma, ревью кода на GitHub, перевод текста, письмо сотруднику, анализ таблицы, сводка литературы, подготовка встречи, и т.п.

Требования:
- В каждом правиле минимум 4 ключевых слова: русские основы И английские.
- Ключевые слова не должны быть слишком общими (не «сделать», не «помочь»).
- Ключевые слова разных правил по возможности не пересекаются.
- promptTemplate на русском, 1-2 предложения, содержит {task}.
Верни ТОЛЬКО JSON-массив из 15 объектов.
````

## 3. Какие системы принимают промпт через URL

**Что вставить:** промпт ниже. Модели нужен доступ в интернет и желательно возможность открывать ссылки.

**Формат ответа:** таблица Markdown + список доказательств.

**Как проверю:** сам открываю каждую ссылку, помеченную «работает»; в панель (`handoff`) вношу только то, что подтвердил сам.

````text
Нужно выяснить, какие ИИ-сервисы позволяют передать готовый текст запроса через параметр в URL, чтобы чат открылся с уже введённым промптом.

Проверь по официальной документации, справке и свежим обсуждениям (укажи ссылки):
1. ChatGPT: https://chatgpt.com/?q=ТЕКСТ
2. Claude: https://claude.ai/new?q=ТЕКСТ
3. Gemini (gemini.google.com): есть ли аналогичный параметр; если нет, так и напиши
4. Любые другие чат-сервисы, которые это поддерживают (кратко, до 3)

Для каждого сервиса дай:
- работает ли параметр: «да» / «нет» / «не подтверждено»
- точный шаблон URL с {prompt} вместо текста
- нужно ли кодировать текст (encodeURIComponent) и есть ли ограничение длины
- отправляется ли промпт автоматически или только подставляется в поле ввода
- что будет, если пользователь не авторизован
- ДОКАЗАТЕЛЬСТВО: ссылка на документацию или цитата; если доказательства нет, ставь «не подтверждено»

Формат ответа: таблица Markdown (сервис, работает, шаблон URL, кодирование/длина, автоотправка, доказательство), затем список ссылок на источники. Не выдумывай: «не подтверждено» лучше неверного «да».
````

## 4. Smoke-тест интерфейса (Playwright или Puppeteer)

**Что вставить:** промпт ниже.

**Формат ответа:** один файл `tests/smoke.js` + команда запуска + список проверок.

**Как проверю:** запускаю на своём сервере с тестовым паролем; тест должен проходить, а при намеренной поломке (например, остановленный сервер) падать.

````text
Напиши smoke-тест веб-интерфейса на Playwright (Node.js, CommonJS, один файл tests/smoke.js). Без других зависимостей.

Приложение: локальный сервер, адрес из переменной окружения BASE_URL (по умолчанию http://127.0.0.1:8787), пароль из переменной PASSWORD (может быть пустым — тогда авторизации нет).
API:
- GET /api/health -> {ok:true, version, authRequired}
- POST /api/login {password} -> {ok:true}, cookie aid_session; 401 при неверном пароле
- GET /api/config -> {version, systems[], tools[], connections[], rules[], settings}
- POST /api/recommend {task} -> {matchedRule, best, alternative, prompt, ...}
- GET /api/export -> файл config.json
Интерфейс (русский): вкладки «Системы», «Матрица», «Кому дать задачу», «Настройки»; на вкладке «Кому дать задачу» есть textarea, кнопка «Подобрать» и результат с блоком промпта; на «Настройки» есть кнопка экспорта; карточки с demo:true помечены текстом «ДЕМО».

Тест должен:
1. Проверить /api/health (200, ok:true).
2. Если authRequired: сначала проверить, что неверный пароль даёт ошибку, затем войти верным.
3. Открыть каждую из 4 вкладок и убедиться, что содержимое видно.
4. На «Системы» убедиться, что есть хотя бы одна карточка.
5. На «Кому дать задачу» ввести «найти письмо от главврача», нажать «Подобрать», дождаться результата с непустым промптом.
6. Проверить, что на странице нет ошибок в консоли (console.error) и нет горизонтальной прокрутки при ширине окна 360px.
7. Вывести понятный итог: список пройденных и упавших проверок; код выхода 0 или 1.

Не используй сторонние тест-раннеры. Добавь в начало файла комментарий с командами установки и запуска.
Верни: код файла, команду запуска, список проверок.
````

## 6. SVG-иконки систем

**Что вставить:** промпт ниже.

**Формат ответа:** по одному блоку `<svg>` на систему, с подписью-именем файла.

**Как проверю:** парсю как XML, проверяю отсутствие `<script>`, внешних ссылок и обработчиков `on*`; смотрю в браузере в светлой и тёмной теме.

````text
Нарисуй простые собственные SVG-иконки для 3 систем: chatgpt, claude, gemini.

Требования:
- НЕ копировать логотипы компаний и не воспроизводить их товарные знаки. Это нейтральные абстрактные значки (геометрическая фигура + буква), узнаваемые по цвету и форме внутри панели.
- viewBox="0 0 48 48", без width/height, без текста-шрифтов (букву рисовать path'ом или использовать простую фигуру).
- Цвета через currentColor и один акцентный цвет; должны читаться на светлом и тёмном фоне.
- Размер каждого файла до 1 КБ.
- Запрещено: <script>, <style> с @import, внешние ссылки (href/xlink:href на http), атрибуты on*, <image>, <foreignObject>.
- Для доступности: <title> внутри svg с названием системы.
````

## 7. Ревью `server.js` на безопасность

**Что вставить:** промпт ниже и ПОЛНЫЙ текст `server.js` (вставляю я по запросу; `data/.env` не вставлять).

**Формат ответа:** таблица по пунктам чек-листа: OK / ПРОБЛЕМА / НЕ ПРИМЕНИМО, строка кода, пояснение, предложенное исправление.

**Как проверю:** каждую «ПРОБЛЕМУ» перепроверяю по коду сам и воспроизвожу; ложные срабатывания отбрасываю; исправления вношу сам.

````text
Ты проводишь ревью безопасности Node.js-сервера (server.js) без внешних зависимостей. Это личная панель, может быть доступна с телефона по VPN (Tailscale/WireGuard), поэтому внешний доступ возможен.

Ниже код. Пройди по чек-листу и по КАЖДОМУ пункту выдай строку таблицы: пункт | вердикт (OK / ПРОБЛЕМА / НЕ ПРИМЕНИМО) | номер строки или функция | пояснение | как исправить.

Чек-лист:
1. Пароль сравнивается через crypto.timingSafeEqual (с учётом разной длины).
2. Задержка/ограничение при неверном пароле; нет ли возможности перебора без ограничения.
3. Токен сессии: crypto.randomBytes(32), хранение, срок жизни, очистка.
4. Cookie: HttpOnly, SameSite=Lax, Path, Max-Age; Secure не обязателен по HTTP, но отметь.
5. Все /api/* кроме /api/health и /api/login требуют сессию, когда авторизация включена; нет обходов через регистр, двойные слэши, %2e и т.п.
6. Отдача статики: защита от path traversal (../, %2e%2e, обратные слэши, null-байт); отдаются только файлы из public/; data/, .env, .sessions.json, server.log недоступны.
7. Секреты не попадают в /api/config, /api/export, логи, сообщения об ошибках.
8. Логи не содержат тел запросов, Cookie, Authorization, паролей.
9. Лимит размера тела запроса; обработка некорректного JSON без падения процесса.
10. Валидация входных данных (PUT /api/config, /api/import, /api/connections): типы, длины, id как slug, защита от __proto__/constructor/prototype.
11. Атомарная запись файлов (tmp -> rename); права на файлы с секретами.
12. POST /api/check/:systemId: нет SSRF-проблем (ограничение схем http/https, таймаут, нет следования опасным редиректам, не отдаётся тело ответа).
13. Заголовки: X-Content-Type-Options: nosniff, Referrer-Policy: no-referrer, Cache-Control: no-store для API; отметь отсутствие CSP и предложи значение.
14. CSRF: изменяющие запросы (POST/PUT/DELETE) требуют Content-Type: application/json или проверку Origin.
15. Привязка к HOST: по умолчанию 127.0.0.1; при HOST != 127.0.0.1 без пароля сервер отказывается стартовать.
16. Необработанные исключения не раскрывают stack trace клиенту.

Не придумывай проблем, которых нет в коде; если не уверен, пиши «не уверен» и почему.
````
